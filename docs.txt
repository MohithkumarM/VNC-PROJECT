================================================================================
1. PROJECT OVERVIEW
================================================================================

Project Name: VNC Security Monitor
Type: Machine Learning-based Intrusion Detection System (IDS)
Domain: Cybersecurity / Network Security
Target: VNC (Virtual Network Computing) Protocol

Purpose:
--------
This system monitors VNC connections in real-time and uses Machine Learning
to detect data exfiltration attacks. Data exfiltration is when attackers
steal sensitive data through network connections without authorization.

VNC is a remote desktop protocol used to control computers remotely.
Attackers can exploit VNC connections to:
- Steal files
- Capture screens
- Log keystrokes
- Hijack clipboard data
- Launch denial-of-service attacks

This system detects these attacks automatically using AI.

================================================================================
2. PROBLEM STATEMENT
================================================================================

Traditional firewalls and antivirus software cannot detect sophisticated
attacks on VNC connections because:

1. VNC traffic looks like normal network traffic
2. Attackers use encrypted channels
3. Small data transfers go unnoticed
4. Pattern-based detection fails against new attacks

Challenge:
----------
How can we detect malicious activity in VNC traffic in real-time without
blocking legitimate users?

Solution:
---------
Use Machine Learning to analyze traffic patterns and behavior, not just
signatures. ML models can learn what "normal" looks like and flag anomalies.

================================================================================
3. SOLUTION APPROACH
================================================================================

This project uses an ENSEMBLE approach - combining multiple ML models:

1. Random Forest Classifier
   - Decision tree-based
   - Good for structured data
   - Fast predictions

2. SVM (Support Vector Machine)
   - Linear classification
   - Good for binary decisions (attack/normal)

3. XGBoost
   - Gradient boosting
   - High accuracy
   - Handles imbalanced data

4. CNN (Convolutional Neural Network) - Optional
   - Deep learning
   - Pattern recognition
   - Requires TensorFlow

5. Autoencoder (Anomaly Detection) - Optional
   - Unsupervised learning
   - Learns normal patterns
   - Flags anything unusual

The ENSEMBLE combines all model predictions using MAJORITY VOTING:
- If 3 out of 4 models say "Attack", the final result is "Attack"
- This reduces false positives and increases reliability

7. MACHINE LEARNING MODELS (DETAILED)
================================================================================

A. RANDOM FOREST CLASSIFIER
----------------------------
File: models/random_forest_model.joblib
Scaler: models/rf_scaler.joblib

How it works:
- Creates 100 decision trees
- Each tree votes on the prediction
- Majority vote wins

Features used: 27 numerical features extracted from traffic
Accuracy: ~70-80% on test data

Pros:
- Fast training and prediction
- Handles missing data
- No scaling required (but we scale anyway)

Cons:
- Can overfit on small datasets
- Less accurate than deep learning

--------------------------------------------------------------------------------

B. SVM (SUPPORT VECTOR MACHINE)
-------------------------------
File: models/svm_model.joblib
Scaler: models/svm_scaler.joblib
Label Encoder: models/svm_le.joblib

How it works:
- Finds a hyperplane that separates attack/normal
- Uses kernel trick for non-linear separation

Kernel: RBF (Radial Basis Function)
C parameter: 1.0 (regularization)

Pros:
- Works well with high-dimensional data
- Memory efficient

Cons:
- Slow on large datasets
- Requires feature scaling

--------------------------------------------------------------------------------

C. XGBOOST (EXTREME GRADIENT BOOSTING)
--------------------------------------
File: models/xgboost_model.json
Label Encoder: models/xgboost_le.joblib

How it works:
- Builds trees sequentially
- Each tree corrects errors of previous trees
- Uses gradient descent optimization

Parameters:
- max_depth: 6
- learning_rate: 0.1
- n_estimators: 100

Pros:
- Handles imbalanced data
- Built-in regularization
- Often wins ML competitions

Cons:
- More hyperparameters to tune
- Can overfit if not careful

--------------------------------------------------------------------------------

D. AUTOENCODER (ANOMALY DETECTION)
----------------------------------
File: models/autoencoder_model.h5
Threshold: models/autoencoder_threshold.json

Architecture:
Input (27) -> 64 -> 32 -> 16 -> 32 -> 64 -> Output (27)

How it works:
- Trained ONLY on normal traffic
- Learns to compress and reconstruct normal patterns
- If reconstruction error > threshold, it's an anomaly (attack)

Activation: ReLU (hidden), Sigmoid (output)
Loss: Mean Squared Error

Pros:
- Unsupervised (no attack labels needed)
- Detects unknown attack types

Cons:
- Requires TensorFlow
- Threshold tuning is tricky

--------------------------------------------------------------------------------

E. CNN (CONVOLUTIONAL NEURAL NETWORK) - Optional
------------------------------------------------
File: models/cnn_model.h5
Scaler: models/cnn_scaler.joblib
Label Encoder: models/cnn_le.joblib

Architecture:
- Reshapes features into 2D (like an image)
- Applies convolution filters
- Dense layers for classification

Pros:
- Can detect complex patterns
- Works well with sequential data

Cons:
- Requires more data
- Slower to train
- Needs TensorFlow

--------------------------------------------------------------------------------

F. ENSEMBLE PREDICTOR (VOTING)
------------------------------
File: ml_models/ensemble_predictor.py

How voting works:
1. Each model makes a prediction
2. Predictions are collected: [RF: Attack, SVM: Normal, XGB: Attack]
3. Majority wins: Attack (2 votes) > Normal (1 vote)
4. Confidence = votes_for_winner / total_votes = 66%

Fallback:
- If a model fails to load, it's excluded from voting
- System works with even 1 model loaded

8. HOW THE DETECTION WORKS (STEP BY STEP)
================================================================================

STEP 1: Traffic Capture (Simulated)
-----------------------------------
In production, you would capture real VNC packets using tools like:
- Scapy (Python library)
- tcpdump
- Wireshark

In this demo, we SIMULATE traffic using the Attack Simulator.

STEP 2: Feature Extraction
--------------------------
Each network connection is converted into 27 numerical features:

| Feature         | Description                        | Example    |
|-----------------|------------------------------------|------------|
| PacketSize      | Size of packet in bytes            | 512        |
| ResponseTime    | Time to get response (ms)          | 25.5       |
| Protocol        | TCP/UDP (encoded as number)        | 1 (TCP)    |
| SrcPort         | Source port number                 | 5900       |
| DstPort         | Destination port number            | 49152      |
| PacketRate      | Packets per second                 | 150.0      |
| FlowDuration    | Duration of connection (ms)        | 5000       |
| NumPackets      | Total packets in flow              | 100        |
| PayloadSize     | Data payload size                  | 256        |
| FlagCount       | TCP flags count                    | 3          |
| AnomalyScore    | Pre-computed anomaly indicator     | 0.15       |
| Entropy         | Randomness of payload              | 0.75       |
| BytesSent       | Total bytes sent                   | 15000      |
| BytesReceived   | Total bytes received               | 12000      |
| FlowRate        | Bytes per second                   | 3000.0     |
| ActiveTime      | Time connection was active         | 4500       |
| IdleTime        | Time connection was idle           | 500        |
| ... and more    |                                    |            |

STEP 3: Feature Scaling
-----------------------
Features are normalized using StandardScaler:
- Mean = 0, Standard Deviation = 1
- This helps ML models converge faster

STEP 4: Model Prediction
------------------------
Each model receives the scaled features and outputs:
- Class label: "Normal", "DoS", "Malware", "PortScan", etc.
- Probability/Confidence

STEP 5: Ensemble Voting
-----------------------
All predictions are combined:
- RF says: DoS
- SVM says: Normal
- XGBoost says: DoS
- Final: DoS (majority)

STEP 6: Alert Generation
------------------------
If attack detected:
- Create alert with severity (warning/danger)
- Add protection advice
- Store in database
- Send to dashboard

STEP 7: Dashboard Update
------------------------
Every 3 seconds:
- Frontend calls /api/stats
- Updates charts and numbers
- Shows new alerts

14. ATTACK TYPES DETECTED
================================================================================

1. DoS (Denial of Service)
--------------------------
Description: Flooding server with requests to make it unavailable
Indicators:
- Very high packet rate (>1000/sec)
- Many packets from single source
- Small payload sizes
Protection:
- Block source IP
- Rate limiting
- DDoS mitigation service

2. DDoS (Distributed DoS)
-------------------------
Description: DoS from multiple sources
Indicators:
- High packet rate from many IPs
- Synchronized timing
- Similar packet patterns
Protection:
- Cloud-based DDoS protection
- Traffic scrubbing
- Anycast network

3. Port Scan
------------
Description: Scanning for open ports to find vulnerabilities
Indicators:
- Connections to many ports
- Sequential port numbers
- Quick connection/disconnect
Protection:
- Block scanning IPs
- Port knocking
- Reduce exposed ports

4. Malware
----------
Description: Malicious software communication
Indicators:
- Unusual payload entropy
- Known malware signatures
- Suspicious C2 communication
Protection:
- Antivirus/EDR
- Network segmentation
- Block known malware IPs

5. File Exfiltration
--------------------
Description: Stealing files through VNC
Indicators:
- Large data transfers (>100MB)
- Unusual transfer times
- Bulk file access
Protection:
- DLP (Data Loss Prevention)
- Monitor large transfers
- Encrypt sensitive files

6. Clipboard Hijacking
----------------------
Description: Stealing clipboard data
Indicators:
- High clipboard command frequency
- Large clipboard data size
- Unusual copy patterns
Protection:
- Disable clipboard sharing
- Monitor clipboard activity
- Clear clipboard on disconnect

7. Screen Capture
-----------------
Description: Capturing screen content
Indicators:
- High framebuffer request rate
- Full screen updates
- Regular interval captures
Protection:
- Detect screen recording
- Watermark sensitive screens
- Limit framebuffer rate

8. Keylogging
-------------
Description: Recording keyboard input
Indicators:
- High key event frequency
- Key timing patterns
- Unusual input sequences
Protection:
- Virtual keyboards for sensitive input
- Monitor key event patterns
- Encrypt keyboard data

17. TROUBLESHOOTING
================================================================================

PROBLEM: Dashboard shows "Offline"
----------------------------------
Cause: Browser cannot reach the Flask server
Solutions:
1. Check if terminal shows "Running on http://..."
2. Refresh the page (Ctrl+R)
3. Check if port 5000 is available
4. Disable firewall temporarily

PROBLEM: ML Models show "Not Loaded"
------------------------------------
Cause: Model files missing or corrupted
Solutions:
1. Run: python train_all_models.py
2. Check models/ folder for .joblib files
3. Check terminal for error messages
4. Verify dataset exists in data/kaggle_dataset/

PROBLEM: "ModuleNotFoundError"
------------------------------
Cause: Dependencies not installed
Solutions:
1. Activate virtual environment
2. Run: pip install -r requirements.txt
3. Check Python version (need 3.8+)

PROBLEM: TensorFlow not available
---------------------------------
Cause: TensorFlow not installed
Solutions:
1. Install: pip install tensorflow
2. Or skip CNN/Autoencoder models (system works without them)

PROBLEM: Charts not updating
----------------------------
Cause: JavaScript error or API issue
Solutions:
1. Open browser console (F12)
2. Check for errors
3. Verify /api/stats returns data
4. Clear browser cache (Ctrl+Shift+R)

PROBLEM: Simulation not working
-------------------------------
Cause: Attack simulator error
Solutions:
1. Check terminal for errors
2. Verify models are loaded
3. Check /api/simulate endpoint

PROBLEM: PDF report fails
-------------------------
Cause: ReportLab not installed
Solutions:
1. Install: pip install reportlab fpdf2
2. Check reports/ folder permissions
